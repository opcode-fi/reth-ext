# engineering rules

## COMMENTS
- **YOU ARE BANNED FROM WRITING COMMENTS IN CODE.** IF YOU WANT TO EXPRESS A PROPERTY, EXPRESS IT IN CODE. AN ESSAY OVER A LINE DOES NOT CHANGE ITS BEHAVIOUR, IT ONLY CONFUSES SUBSEQUENT AGENTS AND HUMANS. RENAME THE THING, SPLIT THE FUNCTION, MAKE THE ILLEGAL STATE UNREPRESENTABLE.
- ONE SHORT SENTENCE PER STRUCT FIELD IS ALLOWED — SEE `FetchConfig`. THAT IS THE WHOLE ALLOWANCE IN LIBRARY CODE.
- IN TESTS, ONE SENTENCE ON THE PROPERTY BEING ENFORCED IS ALLOWED.
- BANNED FROM MAKING `tracing` LOGS LOOK LIKE COMMENTS. LOGS SHOW WHAT THE PROGRAM IS DOING, THEY DO NOT EXPLAIN YOUR CODE.
- BANNED FROM MAKING ERROR MESSAGES LOOK LIKE COMMENTS. A FAILURE IS A TYPED ENUM VARIANT HOLDING THE OFFENDING VALUES IN FIELDS; ITS `#[error(…)]` IS A TERSE LABEL, NEVER A `format!` PROSE ESSAY. SEE `SimError`.
- BANNED IN `Cargo.toml`.
- THE PUBLIC-FACING PROSE LIVES IN `README.md` AND `docs/DESIGN.md`. THAT IS WHERE EXPLANATION GOES. `deploy/` AND THE MARKDOWN ARE THE ONLY PLACES A READER-ORIENTED COMMENT IS DEFENSIBLE, BECAUSE STRANGERS RUN THOSE FILES BLIND.

## STRUCTURE
- REPRESENT A FIXED SET OF CHOICES AS AN ENUM, NOT STRINGS. `CommitValidation`, `StateValidity`, `FetchKind` ARE THE PATTERN.
- USE SERDE DERIVES, DON'T IMPL YOUR OWN.
- WHEN MOVING CODE, DO NOT SHIM IT BY REEXPORTING. FIX THE ENTIRE PATH.
- NEVER RUN RAYON IN AN ASYNC RUNTIME. IT DEADLOCKS.
- NEVER RETURN `Option` FOR A FAILURE. RETURN `Result` WITH `thiserror`. `Option` ONLY WHERE `None` IS CORRECT OPERATION.
- FOR ETHEREUM TYPES USE THE REAL RUST COUNTERPARTS (`Address`, `B256`, `U256`, `Bytecode`), NEVER STRINGS OR `Vec<u8>`.
- DON'T MIRROR A CONFIG STRUCT INTO A SECOND RUNTIME STRUCT. `FetchConfig` IS `Copy` AND IS PASSED AROUND DIRECTLY.

## ERRORS
- DO NOT REMAP ERRORS CASE BY CASE. CONTAIN THE INNER ERROR IN A VARIANT AND `impl #[from]` SO LIBRARY CALLS UNWRAP WITH `?`. SAVES HUNDREDS OF LOC.

## STD
- HASHBROWN, NOT `std::collections::HashMap`/`HashSet`.
- PARKING_LOT, NOT `std::sync::Mutex`/`RwLock`. STD POISONS ON PANIC: ONE PANIC UNDER THE GUARD AND EVERY LATER `.lock().unwrap()` PANICS FOREVER. PARKING_LOT DOES NOT POISON, WHICH IS WHY IT HAS NO `.unwrap()`. NO EXCEPTIONS, INCLUDING EXAMPLES.
- `crossbeam-channel` FOR THE SYNC SIDE OF THE `DatabaseRef` BRIDGE, `tokio` CHANNELS FOR THE ASYNC SIDE. THEY MEET IN `await_fetch`. DO NOT BLOCK A TOKIO WORKER ON A CROSSBEAM RECV ANYWHERE ELSE.

## FUNCTIONS
- ONLY CREATE A FUNCTION IF IT IS ACTUALLY REUSED, OR IF IT PROVES A PROPERTY MORE COMPLICATED THAN AN IF STATEMENT SO IT CAN BE TESTED. `validate_chain_committed` EARNS ITS EXISTENCE; A FUNCTION THAT ADDS FOUR ARGUMENTS DOES NOT.
- DON'T `#[allow(clippy::too_many_arguments)]`. IT IS A HINT THAT THE CODE IS SHIT.
- IF THE ARGS ARE THE FIELDS OF THE VALUE YOU RETURN, TAKE THE STRUCT IN. A BUILDER IS NOT THE ANSWER.

## VARIABLES
- DON'T CREATE VARIABLES ONLY TO PASS THEM TO FUNCTIONS. IF THEY ARE GROUPED IN A STRUCT, PASS THE STRUCT OR PUT THE FUNCTION ON IT.
- VARIABLES AS GUARDS WHEN UNWRAPPING RESULTS BEFORE FURTHER COMPUTATION ARE FINE.

## TESTS
- THE TEST SUITE HERE IS GOOD AND IS THE REASON THIS CODE CAN BE CHANGED AT ALL. 63 OFFLINE TESTS IN `rex-sim`: SNAPSHOT CONSTRUCTION, THE CONTINUITY VERDICTS, AND THE FETCH MANAGERS AGAINST `MockRpc`. KEEP IT THAT WAY.
- A GOOD TEST ENFORCES NON-TRIVIAL LOGIC WE WROTE. TAG INVALIDATION, EPOCH GUARDING, FLUSH DRAIN, REORG TRUNCATION, CODE-HINT RESOLUTION — THOSE ARE WORTH TESTS.
- TESTS THAT ASSERT LANGUAGE PRIMITIVES WORK ARE BANNED. IF STATEMENTS WORK. ARITHMETIC WORKS. SERDE SERIALIZES. A TEST THAT CHECKS A FUNCTION RETURNS AN ERROR WHEN A KEY IS MISSING IS 30 WASTED LINES — READ THE BODY.
- ANY TEST NEEDING A LIVE NODE IS `#[ignore = "requires running node"]`. `cargo test` MUST STAY GREEN OFFLINE ON A FRESH CLONE.

## CHANGING STATE-TRANSITION LOGIC
- `changeset.rs`, `transitions.rs` AND `validation.rs` DECIDE WHETHER THE SIM IS CORRECT. A CHANGE THERE IS NOT DONE WHEN `cargo test` PASSES.
- REPLAY IT: CAPTURE NOTIFICATIONS WITH `rex-cons`'s `subscribe` EXAMPLE, THEN RUN `cargo run --release --example test_artifacts`. IT EXERCISES COMMITS **AND** REORGS AGAINST THE REAL CHANGESET MANAGER.
- THEN PROVE IT AGAINST THE CHAIN: `cargo run --release --example parity -- <rex> <rpc> both`. IT RE-EXECUTES EVERY TRANSACTION OF EACH LIVE BLOCK AGAINST THE SNAPSHOT AND DIFFS AGAINST THE NODE'S OWN `eth_call` AND `eth_simulateV1`. QUOTE THE PARITY RATE. A CHANGE THAT MOVES IT DOWN IS A REGRESSION NO MATTER HOW GOOD THE REASONING WAS.
- NEVER WEAKEN THE STALENESS LATCH TO MAKE SOMETHING PASS. REFUSING TO SERVE UNPROVABLE STATE IS THE POINT.

## CARGO LAYOUT
- FIVE STANDALONE CARGO PROJECTS UNDER `crates/`, NO WORKSPACE, EACH WITH ITS OWN `Cargo.lock`. DO NOT "TIDY" THIS INTO A WORKSPACE WITHOUT PROVING ALL FIVE STILL BUILD — `reth-rex` DRAGS THE WHOLE NODE TREE AND PINS `alloy-rpc-types` EXACTLY.
- LOCKS ARE COMMITTED AND `--locked` IS THE INTENDED BUILD. EVERY RETH DEPENDENCY IS A GIT TAG PIN.
- BUMPING RETH MEANS BUMPING THE TAG IN ALL THREE MANIFESTS THAT DEPEND ON IT — `reth-rex`, `rex-cons`, `rex-sim` — AND REGENERATING EVERY LOCK IN THE SAME CHANGE. A SPLIT BUMP GIVES TWO SIDES OF THE WIRE DIFFERENT BINCODE LAYOUTS AND THE STREAM SILENTLY FAILS TO DECODE.
- `crates/rex-cons/artifacts/` IS GITIGNORED AND IS MULTI-GB. NEVER ADD IT.

## BEHAVIOUR
- DON'T MAKE THINGS UP. IF YOU DID NOT READ IT, IT IS NOT REAL. EVIDENCE FOR CLAIMS REQUIRED.
- ALWAYS MEASURE IN RELEASE. DEBUG REVM IS ORDERS OF MAGNITUDE SLOWER AND A DEBUG NUMBER IS A MEASUREMENT OF A DIFFERENT THING. `cargo test`/`cargo clippy` IN DEBUG ARE FINE.
- FADING CLIPPY WARNINGS IS BANNED.
- WHEN UPGRADING A PART OF THE SYSTEM, FIND EVERYTHING THAT IS NOW UNUSED AND DELETE IT.
- HASHMAPS AND HASHSETS ARE NOT ORDERED.

## GIT
- DON'T PUSH, DON'T CREATE BRANCHES OR WORKTREES. WRITE ON THE CURRENT BRANCH.
- DON'T COMMIT UNLESS ASKED. WHEN ASKED, NEVER ADD A CO-AUTHOR TRAILER.
- THIS REPO IS PUBLIC — RE-READ THE FIRST SECTION BEFORE STAGING ANYTHING.
